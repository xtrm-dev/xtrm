XTRM Agent Runtime Integration Plan v1

Archived initial artifact. This was the first visual design pass produced before the Substrate Task Plan / PR #188 consistency revision. The current canonical design is ../xtrm-agent-runtime-design.md and the superseding visual artifact is ../xtrm-agent-runtime-substrate-work-ux-v2.html.

Decisions retained by v2

  • Agents are XTRM-aware by default; basic system orientation must not depend on manual skill invocation.
  • The first-party communication capability is xtrm-intercom.
  • Mature behavior from pi-intercom and pi-claude-link should be adopted nearly completely.
  • Only the background-process subset of pi-background-tasks belongs in xtrm-background.
  • using-xtrm and multiplexing should shrink to deeper procedural/reference guidance.
  • Persistent Python-kernel guidance should be part of the default capability profile.
  • Specialists/Channels/Substrate remain semantic authorities; communication/background tools do not become workflow authorities.
  • TUI and GUI should consume the same semantic runtime models.
  • Upstream projects remain active watch/contribution sources after first-party adoption.

Why v2 supersedes this artifact

The next design pass integrated the merged Substrate PR #188 terminal UX contract and added a first-class Substrate-backed Issue Task Plan inspired by the mature pi-tasks interaction model. It also made attribution a durable design requirement through ADOPTION-CREDITS.md.

Preservation note

This archived artifact intentionally preserves the initial design stage as a durable project artifact while directing implementers to the current canonical contract. Do not dispatch implementation from this archive when it conflicts with v2.
