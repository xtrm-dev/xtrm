# Handoff and Closeout (canonical Substrate-native doctrine)

Handoff preserves continuity; closeout settles authority. Both rest on the same
durable sources so a fresh worker reaches the executable state from Issue
revision plus capsule plus journal delta alone, without previous chat history.

## Initialization (ADR §72)

If Substrate reports this repository is uninitialized: run `sb init`.

```text
sb init
```

Never guess the only project, invent a project id, or manually create/link
during normal work. Contract changes use only `sb issue edit` and
`sb plan apply`; progress uses the Journal.

## Authority handoff preserves

The executable contract is a ready Issue revision: PROBLEM, SUCCESS, SCOPE,
NON_GOALS, CONSTRAINTS, VALIDATION, OUTPUT, plus SCRUTINY, ownership, and
context. Handoff never moves authority: the Issue stays authority, and a
bounded Journal handoff/checkpoint entry carries blockers, known pending work,
and provenance refs. The next worker restarts from `sb issue resume`.

```text
sb issue show <ref>                 # exact revision under handoff
sb issue validate <ref>             # readiness still current
sb issue attest <ref> --outcome ready --policy <p> --attested-by <who>
sb issue claim <ref> --holder <who>   # atomic lease; not an assignee label
sb issue resume <ref>               # Resume Capsule
sb journal since <ref> <cursor>     # delta reads only
sb journal checkpoint <ref>         # mechanical checkpoint first
sb provenance trace <ref>           # what execution produced
```

`sb issue edit <ref> --title … --priority …` is metadata (no revision);
`--contract … --ownership … --context-refs … --scrutiny …` is
execution-bearing (new revision, readiness invalidated). Graph moves
(`sb issue relate / unrelate --from <a> --to <b> --kind …`) never touch the
contract. Mutation requires a live claim on the Issue (`sb issue claim` /
`sb issue release`). Substrate provides no workspace-exclusion guarantee: the
Specialists activation layer owns workspace exclusion.

## Journal kinds (ADR §73)

Canonical guidance:

```text
material fact
→ finding

architectural choice
→ decision

blocked condition
→ blocker

progress boundary
→ milestone

handoff
→ handoff

completed bounded run
→ result

ordinary useful annotation
→ note


authorized work changed
→ STOP
→ /planning
→ new Issue revision
```

Live verbs (append-only; notes never bump the revision):

```text
sb issue note <ref> "text" --kind note|finding|decision|blocker|milestone|handoff|result
sb journal append <ref> --kind finding|decision|blocker|milestone|handoff|result|checkpoint|compaction|note
sb journal checkpoint <ref>             # mechanical checkpoint at durable boundaries
sb journal show <ref> / sb journal since <ref> <cursor> / sb journal render <ref>
sb issue note <ref> "…" --kind handoff  # continuation entry for the next worker
```

Do not journal every shell command, every tool call, chain-of-thought,
transient speculation, or routine exploration. Journal high-signal durable
facts only: a material finding, an important decision, an external blocker, a
meaningful milestone, a handoff, a result, and a checkpoint.

If authorized work changed, execution pauses → `/planning` → new Issue revision
→ new readiness attestation → execution resumes. Never smuggle new scope into
prompts, messages, or journal entries.

## Handoff methodology

Handoff = Issue stays authority + bounded Journal handoff/checkpoint entry +
blockers + known pending work + provenance refs; the next worker uses the
capsule. No long transcripts in the Journal. Before compaction, exit, handoff,
or close: mechanical checkpoint first (`sb journal checkpoint <ref>`; durable
even if everything after fails), optional semantic enrichment after, then
continue from the capsule. If a summary disagrees with Issue/Journal/provenance
state, durable Substrate state wins.

Normal continuation reconstructs from current Issue revision plus latest
checkpoint plus Journal delta since checkpoint plus claim plus blockers plus
child status plus pending asks plus provenance state. This produces the Resume
Capsule. A worker should not need the previous chat transcript.

## Closeout (ADR §75)

Before closure: SUCCESS satisfied, VALIDATION complete, required OUTPUT exists,
material result durable, important decisions/findings durable, provenance
sufficient, and no incompatible blocker remains. Then write structured Closure:

```text
sb issue close <ref> --outcome <completed|superseded|duplicate|wont_fix|invalid|cancelled|abandoned> --reason <r> --result <a,b> --receipt <a,b> --validation <a,b> --artifact <a,b>
sb issue state <ref> done            # lifecycle rest state (close|reopen|defer|cancel|archive aliases)
sb issue release <ref> --holder <who>
```

Do not close solely because a commit exists. Closure answers why the Issue
became terminal; the reason lives in the Closure row, never only in git log.
Stopping one execution is not a close: release the claim instead. Reviewers and
validators are actors; their durable output may include a Journal result,
Journal findings, validation refs, and receipt/evidence refs (example outcome
`PASS_WITH_NOTES`). No commit required.

## Boundaries (ADR §54)

- **Journal != Issue.** Progress entries never modify the contract; only a
  planning revision changes executable authority.
- **Journal != Memory.** Findings never auto-become reusable truth.
- **Messages != authority.** Channel messages coordinate but never silently
  change the contract.
- **Provenance != progress notes.** Executor output is a claim; record what
  execution produced via `sb provenance dispatch <ref>` / `sb provenance trace
  <ref>`, separate from journal progress.

Coordinator workflows periodically inspect children, claims, pending asks, new
results, blockers, provenance, and release gates, and journal only material
root-level state. No giant rewritten root description. No child transcript
duplication. Do not duplicate full child Journal bodies.

No active retired commands. Historical references, where unavoidable, are
explicitly marked as history ("retired", "formerly", "migration") and never as
live workflow. Contract repair always routes through `/planning`.
