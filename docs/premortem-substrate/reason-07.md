The two-tier story has no v0 for the top tier. Substrate's team/company adoption story rests on the "top tier" — Supabase Postgres as a read-mostly projection over the local SQLite store. The doc says the projection is trivial because "no FK cross-domain, correlation by opaque ID makes 1:1 row transfer." But "trivial" is a strong word for what actually has to work: identity stability across machines (`participant_id` consistency when two laptops share a project), reader-side lineage reconstruction from opaque IDs across the network, conflict handling on team-level writes (comments, approvals, optimization decisions), evidence ref resolution when the bottom-tier file the ref points at lives on a different machine, write-coalescing for high-volume `xtrm_forensic_events`. None of this has a v0. Six months in, the bottom tier is shipped solo-user, the top tier never starts because every projection mechanic needed end-to-end design and that design hasn't happened, substrate stays solo-user only, and the team/company adoption story — which justified building five packages instead of one — quietly dies. The architecture cost was paid for an audience that never showed up.
