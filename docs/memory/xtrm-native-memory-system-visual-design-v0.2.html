03

Authority split

PythonExecutionSession owns

  • progressive investigation
  • aggregation
  • comparison
  • retrieval drill-down
  • candidate drafting
  • intermediate result sets
  • evaluation workflows

PythonExecutionSession does not own

  • MemoryRecord promotion
  • supersession/invalidation
  • lifecycle transitions
  • SQLite persistence
  • ACL/capability policy
  • canonical indexing daemon
  • durable namespace persistence
04

Kernel identity and lifecycle

The kernel follows XTRM execution identity, not merely Pi session identity.

execution_id + generationCanonical key for PythonExecutionSession.
provider reconnectMay reuse the same kernel if the logical execution is unchanged.
new attemptMay start a fresh kernel to avoid stale scratch state.
new generationAlways receives a fresh kernel.
terminal executionKernel is killed. Durable state stays in Substrate.
