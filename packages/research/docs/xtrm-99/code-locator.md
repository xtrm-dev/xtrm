# Multi-step showcase: code-locator beam routing (XTRM-512; criterion 10 input)

## Why this experiment exists

The Evidence Gate benchmark tested Jev as a classifier on independent
items. The System One pattern under study is a control loop, in which
many small decisions depend on a changing state. This showcase is the one
multi-step experiment inside XTRM-99. The operator chose it on 2026-09-18,
and it decides criterion 10 together with the cascade.

## Task

Given a task as written **before** the work, walk a repository tree and
rank the files the change actually modified.

- **State:** the first revision of a Substrate issue contract (PROBLEM +
  SUCCESS). An inline `SCOPE:` tail is cut, and path-like tokens are
  replaced by `[path]`.
- **Loop:** one Jev request per step carries one Choice per beam node
  ("which entry of this directory contains the files that this work
  changes?").
  - Code keeps the best 3 directories by geometric-mean probability over
    the answered steps.
  - A directory with a single entry is decided by code, not asked.
  - Files become ranked leaves.
  - The loop stops when no directory is left, or at depth 10.
- **Truth is deterministic, from git:** files with status M in the ref's
  commits that existed at the base commit, minus changelogs and lockfiles.
- **Baselines (free, deterministic):**
  - `lexical`: idf-weighted overlap of task words and path words;
  - `hot-files`: files ranked by how often they were modified before the
    base commit.
- **Data:** 69 tasks, 46 from xtrm (`main`) and 23 from specialists
  (`master`). Dataset sha256
  `cc6a83cc28ea8fc44d8310995c2e1d2651d9e03ebf02df729b6042640bcd160c`,
  frozen at `~/.xtrm/research/datasets/code-locator-v1/`.
- **Spend:** 332 Jev requests, 424,333 input tokens, USD 0.0178.

Disclosed change: a 2-task smoke run showed that a forced single-entry
step inflated a path score (`apps/.gitkeep` ranked first). Path scores
were then changed to average over answered steps only. The 69-task run
used that scoring. No other change was made after seeing results.

## Reading

The following statements are facts, read from the intervals above:

1. **The System One beam finds the changed files better than lexical
   matching.** hit@1 is +0.101 [0.014, 0.203] and MRR is +0.105 [0.014,
   0.197].
2. **A free deterministic prior beats it by a wide margin.** hit@1 is
   −0.304 [−0.420, −0.188] and MRR is −0.245 [−0.354, −0.136] against
   `hot-files`.
   - The gap remains on non-Markdown truth, where hit@1 is −0.349
     [−0.476, −0.230].
   - The gap also remains after reciprocal-rank fusion with the prior.
   - Both of those analyses are exploratory.
3. **It is cheap and fast.** Per task: 4.8 requests, 9.9 questions, USD
   0.000258 and 3.2 s.

Conclusion: in this design, Jev given only the task text adds no value over
a free history prior.

Untested: a design that puts the prior into the state (for example, change
frequency per entry in the Choice criteria), and designs with escalation.
Those are candidates for the follow-up epic, not findings.
