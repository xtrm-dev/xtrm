pi viewer — design document

How the viewer looks, how it is built, and why each rule exists. Every claim cites the file that carries it.

version 22026-11-265 palettes12 sections

Version 2, 2026-11-26 (XTRM-1068). Supersedes the draft of 2026-11-25 (XTRM-1049).

This document records what the viewer is and how it is built. Every behavioural claim cites a file and line, or a Substrate journal entry. Line numbers refer to the tree that carries this document. Where a value lives in CSS, the citation is src/styles.css; where it lives in a component, the citation is that component. Nothing here is a proposal: proposals and unresolved gaps are in §11.

The design language is the console's. packages/xtrm-app/docs/design/console-ui-system.md is the authority for the language; this document is the authority for the viewer's use of it.

1. Purpose and scope

The viewer is a local web application that renders the work of one tmux session as a channel. One tmux session is one channel; the agents are the pi and Claude Code panes inside it. The server reads the agents' transcripts from disk, never attaches to a pane and never owns an agent process (README.md:6). The only write it can perform is tmux send-keys for a message the operator sends from the composer (README.md:140-141). It binds to 127.0.0.1 and has no authentication (README.md:53).

In scope: the reading experience of one operator watching several agents, and answering them.

Out of scope, by decision: starting, steering or approving an agent. Stopping is in scope since 2026-11-26: Escape to the agent's own pane, from the composer, while it works (XTRM-1088). Rows for an interrupt and a pending approval are designed but not built, because nothing may change agent state (XTRM-1024 seq3, §11).

The document covers the browser client, the shape of the server it depends on, the design system it wears, and the evidence behind each. Sibling documents go deeper in one area each: docs/design/working-presence.md (turn state model), docs/design/palette-console.md (region and contrast audit), docs/design/t3code-chat-audit.md (the restyle audit), docs/design/console-shell-spike.md (the shell), docs/design/spacing-reference.md (a density guide, not a source of truth).

2. Principles

  1. Restraint. No new colour and no new tint outside the console's token set. Every surface either

wears an existing token or explains its scoped departure here (console-ui-system.md §2.3).

  1. One shape per state. A state looks the same on every surface that shows it. The status dot is the

one place this is enforced in code: a single table serves the thread, the presence line and the sidebar (src/lib/status-dot.ts:13, :44).

  1. The transcript is the source of truth. The interface derives rows from records and never guesses

an outcome. A prompt is Sent when the keys reached the pane, Seen when the record exists, Replied only when a later turn settled (src/lib/delivery.ts:13-49).

  1. The reader's place is not disturbed. No layout animation, no row that changes height when it

enters the viewport, no scroll that fights the reader's own gesture (src/styles.css:579-581, src/lib/stick.ts:8).

  1. Motion carries meaning or it does not happen. Opacity and a translate of at most 4px, nothing

that changes layout, and every animation has a prefers-reduced-motion branch (console-ui-system.md §18; src/styles.css:583-617, :738-748).

  1. A word can leave the screen, never the accessibility tree. The sidebar dropped the state word in

favour of the dot; the word stayed as the dot's aria-label, its tooltip and part of the row's label (XTRM-1048; src/lib/status-dot.ts:71-90).

  1. Every value is a token. No component holds a raw colour; the @theme block is the only bridge

from --x-* to utility classes (src/styles.css:227-311).

  1. Quiet by default. Chrome does not shout: metadata reveals on hover except where the operator

ruled that it reads at rest, and the transcript itself is the only loud element.

3. Architecture

3.1 Server (packages/pi-viewer/server)

The server is a Vite plugin that answers /api/* and nothing else (server/plugin.ts:24). It runs under npm run dev and under npm run preview alike, because the middleware comes from the plugin (README.md:24-25).

3.3 Data flow, transcript to row

The Channel is a settle-time timeline: an operator message sits at its send time, an agent turn sits at the event that settles it (the final reply), and a running turn is always last. Ordering among items of different rank is fixed by compareChannelItems: user, inbound, optimistic, turn, sent (src/lib/thread.ts).

3.4 Incremental polling and the scope-aware window

The browser loads the newest 150 turns, then polls with since=<cursor>&revision=<id>; a poll returns only new or changed events, before=<cursor> pages backwards, and the client never starts a poll while one is in flight (README.md, "Data model"). The thread poll backs off to 5 s above 800 ms and 10 s above 2 s of response time; discovery runs on the server.

Since XTRM-1066 the request carries the reading scope: p=<paneId> or w=<windowIndex> narrows the window server-side, a malformed scope is a 400, and the revision is tagged per scope, so a scope change is a fresh window rather than a client-side filter over a session-sized payload. Repeat polls at the same cursor are answered from a cached encoded frame keyed by (query, scope, agent-list hash, cursor, revision); a changed agent set returns a reset rather than merging across a broken cursor space (server/thread-cache.ts, server/api.ts; XTRM-1066 journal).

A scope change inside one session keeps the previous screen until the scoped window arrives, and does not clear optimistic messages (src/lib/api.ts, src/App.tsx; XTRM-1066). Rows therefore never flash empty on a click.

4. Design language

4.1 Colour: five palettes, one token set

All colour is a CSS variable on :root (src/styles.css:34-116 light, :118-163 dark), exposed to Tailwind v4 through @theme so no component holds a raw colour (:227-311). A palette is a set of region assignments and, for Desktop, plane values; a theme is light or dark; a soft-text variant is a text-only layer on top of a base palette.

Five palettes ship: Threads (default), Threads · soft text, Console, Console · soft text and Desktop (src/lib/palette.ts:15-17; operator ruling 2026-11-26, §10). The header's Colours control sets data-palette on <html> and the choice persists in localStorage; a theme sets data-theme; a soft-text palette keeps its base's data-palette and adds data-text="soft" (src/lib/palette.ts, src/styles.css:210-225). A switch rewrites variables only: no component fork, no reload, no scroll change.

At 390px: the sidebar is an overlay, the chat lane is the full column, the composer's mouse hint is hidden (sm:block) while the target, model and effort stay on the under-row, presence rows grow to 44px, the operator bubble is capped at 80% of the lane, and every table in rendered markdown scrolls inside its own box. The sidebar gate and the rows gate run at 1440 and 390 in both themes (scripts/sidebar-gate.mjs, scripts/rows-check.mjs).

6.9 Composer, target row and menus

Purpose: send one operator message to one agent, and answer a specific agent without retyping.

Geometry: a 56px one-line box that grows to max-h-52 (208px), no border and no ring in any palette or state, a fill one step above the canvas, a slight drop shadow, 16px/24px prompt, a 32px send button overlaying the box's bottom right, and an empty attach slot on the left for a control that does not exist yet (src/components/Composer.tsx:237-262). The box carries --x-composer-fill, --x-composer-focus, --x-composer-shadow and --x-composer-shadow-focus (.xtrm-composer-box, src/styles.css:749-765), so a palette decides the step, the elevation and the focus signal without touching the component.

The box centres the painted band, not the line box. Inside a 24px line box a font's descender ink is shallower than its cap height, so an evenly padded line draws its ascenders and descenders slightly low in the box; the operator sees that as text sitting under the middle. The textarea therefore carries 3.25px above the line and 4.75px below, and the measurement that binds is the rendered band: at a 2x device ratio the placeholder and a typed line both paint across 20.5–35px of the 56px box, the send glyph across the same band, and every gap is within 0.25px of centre (npm run test:composer asserts this on pixels, not on rects).

The target row sits under the box, right-aligned, 12px apart: the target (status dot, name, chevron), its model, and its bare effort — for example lead claude-opus-4-8 high (:264-341). The values come from the agent's model and thinkingLevel through composerMeta (src/lib/composer-meta.ts); a missing value is omitted, never invented. The row is 14px against the 16px prompt, muted, with no chips and no borders.

Beside the model name the composer draws the agent's context usage (XTRM-1087): a 14px ring whose arc is the fraction of the model's window the transcript fills, with the track at 22% of the tone colour. The tone steps from ink-muted under 75% to ink from 75% and danger from 90%, and the accessible name and tooltip carry the number, for example 46% of 200k tokens (src/components/ContextRing.tsx). The fraction is the newest assistant message's input plus its cached prefix, read from either runtime's transcript, and the window comes from a model table in src/lib/context-usage.ts; a model the table does not know, or an agent with no usage, draws no ring rather than a guess.

The agent menu opens upward from the target it belongs to, anchored to the right edge of the target group so it meets the send button's right edge, sizing to its rows between 14rem and 20rem and never wider than the screen (:270-300). The status word sits on each row's right.

Other states: empty with a placeholder and the mouse hint (@ to mention · Shift+Enter for a new line, text-2xs, hidden below sm); draft; addressed; sending (the send glyph becomes a spinner); error (text-2xs in danger under the box); gone (the target pane left — the composer disables and the reply bar drops, src/lib/reply.ts:14-27).

The composer addresses the pane itself, else the most recently active agent of the scope; @ opens the agent list; Escape clears the reply bar before it clears the draft (src/lib/reply.ts:41). Newlines flatten to spaces for this version (README.md:121). The optimistic user row disappears when the matching user event appears in the transcript.

6.10 Scroll pill, new-since divider and the follow policy

Purpose: keep a reader's place, and show what arrived while they were away.

The pill appears only when the reader is not at the end; it reads Scroll to end, adds · N new, and never steals the composer's focus (src/components/ui/message-scroller.tsx:640-660). The follow policy is one function (src/lib/stick.ts:8): smooth only while at the end and content is arriving, never for a reader who scrolled up, and the reader's own input ends it. A send is the one exception: it pins the viewport to the end even when the reader had scrolled up, and the intent survives the optimistic-to-echo swap and the reply; a wheel, touch, pointer or key gesture clears it so a deliberate scroll-up wins (XTRM-1064).

The new-since divider is a single line, New · N, placed at the first item after the scope's last-read time. The baseline is frozen for the visit, so the divider does not walk away while the reader reads (src/components/ChannelView.tsx, src/lib/readstate.ts:69-103). Operator rows never count as unseen (unseenTimelineItems, :92).

6.11 All-events view

Purpose: the raw event log, for debugging rather than reading.

Loaded on demand as its own chunk (src/App.tsx:51, :552), with a light Loading events… line as the Suspense fallback. It is the one view that renders the model as data: effect, time, agent, payload.

7. Interaction and accessibility

Keyboard. The sidebar is a tree with roving focus (src/components/sidebar/SessionTree.tsx:202); the presence panel is a listbox with its own key handler; the view control is a tablist with two tabs (src/components/ViewerHeader.tsx:30-40); the chat-width control is a radiogroup with radio items and a custom field (:104-142); menus are buttons with aria-expanded that open upward. Ctrl/Cmd+B toggles the sidebar; Escape clears the reply bar, then the draft, then closes an open menu.

Focus. One global :focus-visible rule draws a 2px accent ring with a 1px offset (src/styles.css:333-336). No component removes an outline without replacing it: the resize handle replaces it with an accent line on its own edge (src/shell/resizable.tsx:160), the composer with its inset ring. Collapsing the sidebar moves focus to the reopen button, so focus is never lost.

Labels. Every dot is role="img" with a state word, and carries a title (src/components/sidebar/SidebarDot.tsx, src/components/presence/PresenceLine.tsx). The sidebar row's accessible name ends with that word, so a screen reader hears lead, Claude, pi-viewer, Quiet 16m even though the row shows no word. Delivery marks carry their word and a sentence. Status is never conveyed by colour alone: the dot differs in shape, animation and label.

Live regions. The presence line announces changes politely (aria-live="polite") and never interrupts typing. Nothing else in the viewer is a live region: the thread changes under the reader without announcement, which is correct for a transcript and wrong for an alert.

Contrast. Text meets 4.5:1 and every non-text mark meets 3:1 against the plane it sits on. Two gates hold this: npm run test:contrast measures the status dots in five palettes and both themes, and npm run test:palette measures the palette's text roles per palette and theme. Both fail the run rather than warning.

Reduced motion. Every animation has a branch (§4.5). Under prefers-reduced-motion: reduce the dots stay at full opacity, the shimmer and fades stop, the metadata transition is removed, and colour alone still distinguishes every state.

Pointer. A coarse pointer reveals row metadata at rest (@media (pointer: coarse), src/styles.css:685-689), because hover does not exist there. The resize handle is 8px wide with a 16px keyboard step; the composer's send button is 32px; no transcript row is a pointer target.

Motion and layout stability. No row changes height on entering the viewport — content-visibility is deliberately not used (src/styles.css:579-581). The scroller owns anchoring: rows are indexed once per mutation, offsets are cached, and a reader's position is restored by index rather than by pixel.

8.4 Render cost (XTRM-1065)

The thread no longer remounts on a scope change: the provider is not keyed by scope, and a thread-key effect restores the new thread's position. Rows are memoized, the timeline is built once per payload, and the presence line derives from the same timeline instead of building a second one. Measured on a re-baselined worktree: idle TurnView renders under live writes fell 75% (1128 → 282 in a 4.5 s window), and 93% in a quiet window; a heavy scope switch stayed fetch-bound at 50–100 ms with 106 row renders, i.e. no regression. The first measurement in that issue was discarded because its baseline had no rendered turns, and the corrected numbers replaced it (XTRM-1065 journal, seq 3).

The operator bubble's fold is decided from a text estimate rather than a getComputedStyle + scrollHeight pair per mount, which removed one forced layout per operator message (src/components/ChannelView.tsx:145-148).

9. Turn state model

Summary of docs/design/working-presence.md §8 (authority: XTRM-1043). Three review rounds failed heuristic classification (XTRM-1037, 1040, 1041), so one explicit state machine replaced them (code: src/lib/turn-state.ts).

  • One effect per record. The server classifies every transcript record as open, step, reply,

abort, fail, compact or none, and carries it on the event (entryEffect, server/session.ts:625; ViewerEvent.effect). The table of which records produce which effect, and the three cases the record alone does not settle (Claude slash commands, Pi custom_message wake-up types, Claude stop_sequence), is docs/design/working-presence.md:326-356.

  • States. phase is none, open, settled, aborted or failed; an open turn also records

loop, and a failed one whether the error was a context overflow (src/lib/turn-state.ts:42-54). Transitions are nextTurnState (:66); none never changes the state.

  • Status. The status and its note derive from the phase and the silence: attention on an open

question or plan approval, else quiet after 15 minutes without a turn-moving write, else working; waiting when settled, error when failed, idle otherwise; permission prompts from the pane capture are applied last (server/attention.ts:231).

  • Time. No timer enters the machine. The clock is ViewerAgent.lastWriteAt, the write time of the

newest turn-moving record, a running maximum, clamped to the file time (server/session.ts:691).

  • Grouping. The browser folds the same effects with the same machine (groupAgent,

src/lib/thread.ts; splitPresence, src/lib/presence.ts), so the presence line and the thread cannot disagree about a turn. Meta events that carry an effect reach the browser; rendering still skips meta.

  • Proof. The replay harness writes a transcript one record at a time and checks, after each record,

that a fresh parse equals the incremental one, that no stopped row disappears, and that an open turn exists exactly while the status is live (test/replay/harness.ts). The server reads only trailing records (resolveTurnState, src/lib/turn-state.ts:99-118), which equals a fold from the start.

  • Known limits. The model does not guess a retry before it is written, and an overflow reads as

error until its compaction arrives (docs/design/working-presence.md:481-497).

11. Open questions

  1. Dead sidebar state code. stateOf and STATE_LABEL in src/lib/tree.ts are unused by production

code since the dot carries the state; test/sidebar-tree.test.ts still asserts the three-state mapping. Removal is a code change and belongs to a separate issue (follow-up from XTRM-1048).

  1. The README still describes older geometry. README.md gives the sidebar indent step as 0.75rem

while src/components/sidebar/geometry.ts:11 has INDENT_REM = 0.5, and its checks list predates test:composer, test:scope and measure:load. The README needs its revision; it is outside this issue's scope.

  1. The presence panel has no shortcut. No global key opens it; the proposal is none in v1

(docs/design/working-presence.md).

  1. Agents outside the scope. The presence line counts only the scope; the proposal is to keep it that

way and let the sidebar show the rest (docs/design/working-presence.md).

  1. Interrupt and approve. Approval is designed but not built, because nothing may change agent

state (XTRM-1024 seq3). The interrupt half was ruled on 2026-11-26: stopping by Escape is allowed, and the composer sends it while the target works (XTRM-1088).

  1. Inferred Desktop tokens. Desktop inherits border-muted, border-subtle, border-strong,

ink-faint, hover, pressed and accent from the dark base, and the operator supplied no light values at all, so Desktop in light is Threads light. Both are recorded as inferred in docs/design/palette-console.md; a supplied value would replace an inference.

  1. Discovery runs every 2 s, not 10 s. The contract asked for at least 10 s; the snapshot is refreshed

every 2 s because the thread poll reads agents' modifiedAt and eventCount from it, and a 10 s snapshot would delay new events by up to 10 s. The constant is DISCOVERY_INTERVAL_MS in server/api.ts (XTRM-1066 journal, deviation).

  1. The idle thread poll still repeats the agent list. ThreadPayload.agents is sent on every poll

(about 2.1 kB idle, more with 13 agents). A delta or a separate source would shrink it (XTRM-1066 journal, follow-up).

  1. The composer's attach slot is empty. [data-composer-attach-slot] reserves 32px for a control the

viewer does not have; it is a placeholder for a future attachment affordance (XTRM-1056).

  1. A second resizable panel would need its own offsets. The resize handle is positioned from the

panel's width, which is correct for the shell's single split; a second split would need per-panel offsets (XTRM-1067).
