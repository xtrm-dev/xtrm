The problem it kills

BULKbd prime dumps the store

Session-start injection of the entire memory store. Measured in ~/dev/core: 384,750 bytes ≈ 100k tokens of memories the model must carry (or silently lose to truncation) before any work begins.

TARGETEDretrieve at the moment of need

Nothing is loaded until a trigger fires. The agent interrogates the one file it is about to touch — commits, diffs, memories — and prints a bounded digest. Context cost: kilobytes.

The trigger → preflight ritual

# triggers: about to edit a file · fixing a bug · implementing ·
# gitnexus flags a file/symbol critical or medium impact
preflight(repo, path, n=4)
  ├─ git log --follow --format='%h %ad %s + full body'   # subjects alone hide the why
  ├─ git diff HEAD --stat -- <file>                        # history + working state, together
  ├─ bd memories <basename>                                # prior incidents, constraints
  └─ prints a bounded digest; returns the records          # 0 commits = wrong path (guard)
Read-only (no _AUDIT entries). Verified live on .githooks/pre-push: 10 commits with bodies surfaced d6ca0627 fix(hooks): pre-push chain must exit 0 [exit-status-bug] — corroborating the bd memory about the same incident. Two memory layers agreeing = the system working.

Context-window safety (why the kernel can't bust you)

  • State lives outside the window. 1,430-commit corpora sit in the python process heap; the conversation only sees what a cell prints.
  • Hard output cap per cell: 20KB (head 8KB + tail 4KB + marker), full output spilled to a temp file. Absolute ceiling 200KB.
  • One footgun: the driver evals the last expression — a bare commits as the final line dumps its repr (truncated, but wasteful). End cells with len() / top-N / aggregates.

DRIVER-change lore (two bugs the gates caught)

BUG 1backticks in a docstring

The DRIVER is a TS template literal — a backtick anywhere in the Python source terminates it. Bun failed at parse: expected ";" but found "bd". Fix: no backticks in DRIVER strings.

BUG 2the escape layer ate a backslash

\\n typed through the edit-JSON layer landed as \n in the file; TS translated it into a real newline inside a Python string literal → kernel exited at boot. Diagnosis: extract the DRIVER raw vs runtime (eval the template like TS does) and diff. The file needs \\n.
