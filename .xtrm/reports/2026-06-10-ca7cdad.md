### Narrative

**`packages/mcpq/` — new Python package**

The whole point of the package is to avoid two friction points with the conventional `.mcp.json` route for Docker-sidecar MCP servers: (a) internal sidecars (no host port) are unreachable from the host, and (b) loading 40-50+ tool schemas per session burns context tokens regardless of whether observability work happens that session. Architectural decisions embedded in the diff:

- **Stdlib-only call path** (urllib + subprocess + argparse + dataclasses) so install is `pip install -e packages/mcpq` with zero transitive deps. Build-time `setuptools>=68` is the only external touch.
- **Two transport classes** sharing a `post(url, headers, body) -> Response` interface: `HostTransport` direct urllib for host-reachable servers, `DockerTransport(container)` that shells out to `docker exec -i -- <container> python3 -c "<urllib script>"` for internal sidecars. Critical detail discovered live: target sidecars may be distroless (no curl, no python3) — use a different python3-capable container on the same docker network as the proxy. `infra-prometheus-mcp` works as the proxy for both itself and the distroless `infra-grafana-mcp`.
- **Security boundary at config-load and transport**: scheme allowlist (http/https only) with optional `MCPQ_ALLOWED_HOSTS` env-var allowlist, CRLF/NUL guard on every header value (including server-returned `Mcp-Session-Id`), `^[a-zA-Z0-9][a-zA-Z0-9_.-]*$` container-name regex, walk-up `.mcpq.json` discovery bounded by `$HOME` with `--config FILE` override. Reviewer-confirmed.
- **One-line stderr telemetry on every CLI invocation** (success and error) with no payloads/headers/secrets — `{server, subcommand, tool, duration_ms, outcome, error?}`.
- **Tests structure** mirrors the package: `test_args.py` / `test_validation.py` / `test_config.py` / `test_protocol.py` for unit, plus `test_smoke.py` gated on `docker ps` so the suite is safe to run in any environment.
