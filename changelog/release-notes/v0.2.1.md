# v0.2.1 — Execution identity, provenance links, and the workspace-lease withdrawal

## Summary

0.2.1 is a correctness release on the execution-identity and provenance seam, plus one
schema migration. It adds no feature surface.

The headline change is **migration `v12`**, which drops the `workspace_leases` table. That
workspace writer lease was never invoked: it had no caller in this package, and per-Issue
claims were already the only mutation authority. Workspace exclusion is owned by the
Specialists activation layer. The migration applies automatically when the database is
opened. A client older than this release fails closed against a `v12` database
(`fail-closed: unknown migration version 12 in database`), so upgrade clients together.

The rest closes identity and provenance defects that were found by inspecting live rows
rather than by tests. Execution identity is canonicalised at the write seam instead of
being trusted from the caller, derived from ambient context when a caller states nothing,
and projected back into reads so stored identity stays queryable. Integration journal
envelopes carry ambient holder/activation identity instead of shadowing it with a
session-only context. Receipts link to the commit that carries their work and to the
journal checkpoint that settles them. Beads import preserves source timestamps and
structures contracts faithfully, and a repair entry point fixes boards that an earlier
import already flattened.

## Upgrade notes

1. **Upgrade clients together.** A `v12` database is refused by any client that does not
   know `v12`. The version check is fail-closed by design; run `sb doctor` after an upgrade.
2. **No workspace-lease API remains.** Do not query `workspace_leases` or rely on a
   Substrate claim for cross-Issue workspace exclusion. Claims still fence Issue mutations.
3. **Identity is validated on write.** An XTRM session identity must be a canonical
   lowercase UUID or a tmux session id (`$2`). Provider session labels belong in
   `host.sessionId`. An invalid identity is refused before any row is written.
4. **Historical rows are not rewritten.** Earlier rows keep their stored values; display
   marks a missing participant as `(none recorded)` in the journal and `(unattributed)` in
   the provenance trace.

## Execution identity

- Canonicalisation moved to the write seam, so closure and reopen validate the same way
  journal and provenance writes already did. An invalid identity leaves lifecycle and
  Closure history untouched.
- Journal append derives unstated identity from `XTRM_SESSION_ID`,
  `XTRM_SESSION_NAME`, `SUBSTRATE_HOLDER` and `SUBSTRATE_ACTIVATION_ID` instead of
  shadowing it.
- Stored journal identity is projected into reads, so participant, activation, attempt,
  session and run are queryable rather than envelope-only.
- `--session` overrides `XTRM_SESSION_ID` on journal append/checkpoint and provenance
  dispatch. A canonical mismatch warns on stderr in both human and JSON modes; JSON stdout
  is unchanged.
- A provider-unknown legacy session id stays flat-only: no `host.type` is invented for it.

## Provenance and closure

- Receipts link to the commit that carries their work. Re-binding to the same SHA is
  idempotent; a different SHA fails closed instead of silently re-pointing.
- Receipts can record the journal checkpoint that settled them. Omitting it stores an
  explicit null rather than a guessed latest checkpoint.
- The human provenance trace names each binding's participant, activation, attempt,
  session and run, marks an absent identity as `(unattributed)`, and bounds long sections
  with an omitted-item count. `--json` remains the unbounded machine surface.

## Beads import

- Contracts are structured from recognized headings, including the qualified and combined
  heading forms real exports use. Unrecognized headings are reported, never forced into a
  contract field.
- Source creation, update and close timestamps are preserved, with a documented fallback
  order for terminal time (`closed_at` → `updated_at` → `created_at` → import time) and a
  `timestampProvenance` record per imported row.
- `scripts/repair-beads-import.ts` repairs boards an earlier lossy import already stored.
  It reads the original export, defaults to a dry run, and writes only through typed
  services.

## Provider integrations

- Pi and Claude journal/checkpoint adapters fill unstated participant and activation
  identity from the ambient contract; explicit input still wins, and nothing is invented
  when the ambient state is empty.
- Claude PreCompact and stop checkpoints carry stated or ambient holder/activation.
  PostCompact remains a provider-session-only audit event.
- The Pi compaction result carries summarizer token usage. Usage is not stored in the
  journal checkpoint schema; when a summarizer reports none, absence is recorded as a note
  and no value is estimated.
